## 7.1 抽象数据类型图的定义

> 课件页码：P2–P20

### 一、图的定义

> 课件页码：P2–P4

**定义**：图是由一个顶点集 V 和一个弧集 R 构成的数据结构。

    Graph = (V, R)

其中 VR = {`<v,w>` | v,w∈V 且 P(v,w)}。

- `<v,w>` 表示从 v 到 w 的一条弧，称 v 为弧尾（初始点），w 为弧头（终端点）；谓词 P(v,w) 定义了弧 `<v,w>` 的意义或信息。
- **有向图**：由于“弧”是有方向的，由顶点集和弧集构成的图称作有向图。例如 G1=(V1, VR1)，其中 V1={A, B, C, D, E}，VR1={`<A,B>`、`<A,E>`、`<B,C>`、`<C,D>`、`<D,B>`、`<D,A>`、`<E,C>`}。
- **无向图**：若 `<v,w>`∈VR 必有 `<w,v>`∈VR，则称 (v,w) 为顶点 v 和顶点 w 之间存在一条边；由顶点集和边集构成的图称作无向图。例如 G2=(V2, VR2)，其中 V2={A, B, C, D, E, F}，VR2={`<A,B>`、`<A,E>`、`<B,E>`、`<C,D>`、`<D,F>`、`<B,F>`、`<C,F>`}，其中的元素均成对出现。

> 课件 P2 原文写作“v 为弧头，w 为弧尾”，与“出度是以该顶点为弧尾的弧的数目”这一用法及弧的方向相矛盾；此处按弧的起点为弧尾、终点为弧头整理，以下各节同此约定。

### 二、名词和术语

> 课件页码：P5–P13

课件 P5 列出的名词术语：网、子图；完全图、稀疏图、稠密图；邻接点、度、入度、出度；路径、路径长度、简单路径、简单回路；连通图、连通分量；强连通图、强连通分量；生成树、生成森林。

**网、子图**：设图 G=(V,{VR}) 和图 G′=(V′,{VR′})，且 V′⊆V，VR′⊆VR，则称 G′ 为 G 的子图；弧或边带权的图分别称作有向网或无向网。

**完全图、稀疏图、稠密图**：假设图中有 n 个顶点、e 条边：

| 名称 | 条件 |
|---|---|
| 无向完全图 | e = n(n−1)/2 |
| 有向完全图 | e = n(n−1) |
| 稀疏图 | e < n log n |
| 稠密图 | e ≥ n log n |

**邻接点、度、入度、出度**：

- 若顶点 v 和顶点 w 之间存在一条边，则称顶点 v 和 w 互为邻接点；边 (v,w) 和顶点 v、w 相关联。
- 和顶点 v 相关联的边的数目定义为该顶点的度。例如在无向图中，与顶点 B 关联的边有 3 条，与顶点 A 关联的边有 2 条。
- 对有向图：以 v 为弧尾的弧的数目称作 v 的出度 OD(v)，以 v 为弧头的弧的数目称作 v 的入度 ID(v)，顶点的度 TD(v)=OD(v)+ID(v)。例如：ID(B)=2，OD(B)=1，TD(B)=3。

**路径、路径长度、简单路径、简单回路**：

- 设图 G 中的一个顶点序列 {u=v(i,0), v(i,1), …, v(i,m)=w}，其中 (v(i,j−1), v(i,j))∈VR（1≤j≤m），则称从顶点 u 到顶点 w 之间存在一条路径。
- 路径上边的数目称作路径长度，如长度为 3 的路径 {A,B,C,F}。
- 简单路径：序列中顶点不重复出现的路径；简单回路：序列中第一个顶点和最后一个顶点相同的路径。

**连通图、连通分量**：若图 G 中任意两个顶点之间都有路径相通，则称此图为连通图；若无向图为非连通图，则图中各个极大连通子图称作此图的连通分量。

**强连通图、强连通分量**：对有向图，若任意两个顶点之间都存在一条有向路径，则称此有向图为强连通图；否则，其各个强连通子图称作它的强连通分量。

**生成树、生成森林**：

- 假设一个连通图有 n 个顶点和 e 条边，其中 n−1 条边和 n 个顶点构成一个极小连通子图，称该极小连通子图为此连通图的生成树。
- 对非连通图，则称由各个连通分量的生成树的集合为此非连通图的生成森林。

### 三、图的抽象数据类型与基本操作

> 课件页码：P14–P20

图的数据对象是顶点集 V，数据关系是弧集 VR；其基本操作按用途分为六类：结构的建立和销毁、对顶点的访问操作、对邻接点的操作、插入或删除顶点、插入和删除弧、遍历。

![图的基本操作的六个类别](assets/第07章图/p014.jpg)

*图 7-3 图的基本操作分为六类（课件 P14）*

| 类别 | 操作（函数原型） | 说明 |
|---|---|---|
| 结构的建立和销毁 | `CreatGraph(&G, V, VR);` | 按定义 (V, VR) 构造图 |
| 结构的建立和销毁 | `DestroyGraph(&G);` | 销毁图 |
| 对顶点的访问操作 | `LocateVex(G, u);` | 若 G 中存在顶点 u，则返回该顶点在图中“位置”；否则返回其它信息 |
| 对顶点的访问操作 | `GetVex(G, v);` | 返回 v 的值 |
| 对顶点的访问操作 | `PutVex(&G, v, value);` | 对顶点 v 赋值 value（课件只给出函数原型） |
| 对邻接点的操作 | `FirstAdjVex(G, v);` | 返回 v 的“第一个邻接点”；若该顶点在 G 中没有邻接点，则返回“空” |
| 对邻接点的操作 | `NextAdjVex(G, v, w);` | 返回 v 的（相对于 w 的）“下一个邻接点”；若 w 是 v 的最后一个邻接点，则返回“空” |
| 插入或删除顶点 | `InsertVex(&G, v);` | 在图 G 中增添新顶点 v |
| 插入或删除顶点 | `DeleteVex(&G, v);` | 删除 G 中顶点 v 及其相关的弧 |
| 插入和删除弧 | `InsertArc(&G, v, w);` | 在 G 中增添弧 `<v,w>`；若 G 是无向的，则还增添对称弧 `<w,v>` |
| 插入和删除弧 | `DeleteArc(&G, v, w);` | 在 G 中删除弧 `<v,w>`；若 G 是无向的，则还删除对称弧 `<w,v>` |
| 遍历 | `DFSTraverse(G, v, Visit());` | 从顶点 v 起深度优先遍历图 G，并对每个顶点调用函数 Visit 一次且仅一次 |
| 遍历 | `BFSTraverse(G, v, Visit());` | 从顶点 v 起广度优先遍历图 G，并对每个顶点调用函数 Visit 一次且仅一次 |

> 基本操作中“位置”的含义由具体存储结构决定：在邻接矩阵中为顶点在 `vexs[]` 中的下标，在邻接表中为顶点在 `vertices[]` 中的下标（见 7.2 节）。

## 7.2 图的存储表示

> 课件页码：P21

课件 P21 列出图的四种常用存储表示：

1. 图的数组（邻接矩阵）存储表示
2. 图的邻接表存储表示
3. 有向图的十字链表存储表示
4. 无向图的邻接多重表存储表示

### 一、图的数组（邻接矩阵）存储表示

> 课件页码：P22–P25

**定义**：设图 G=(V,VR) 有 n 个顶点，用 n 阶方阵 A 表示弧（边）的信息：

    A[i][j] = 1   (vi, vj)∈VR
    A[i][j] = 0   (vi, vj)∉VR

无向图的邻接矩阵是对称矩阵；有向图的邻接矩阵为非对称矩阵。

**例（无向图）**：课件 P22 的 6 个顶点 A~F 的无向图，其邻接矩阵为

|     | A | B | C | D | E | F |
|-----|---|---|---|---|---|---|
| A   | 0 | 1 | 0 | 0 | 1 | 0 |
| B   | 1 | 0 | 0 | 0 | 1 | 0 |
| C   | 0 | 0 | 0 | 1 | 0 | 1 |
| D   | 0 | 0 | 1 | 0 | 0 | 1 |
| E   | 1 | 1 | 0 | 0 | 0 | 0 |
| F   | 0 | 0 | 1 | 1 | 0 | 0 |

**例（有向图）**：课件 P23 的 5 个顶点 A~E 的有向图，其邻接矩阵为非对称矩阵。

![有向图的邻接矩阵为非对称矩阵](assets/第07章图/p023.jpg)

*图 7-4 有向图的邻接矩阵为非对称矩阵（课件 P23）*

|     | A | B | C | D | E |
|-----|---|---|---|---|---|
| A   | 0 | 1 | 0 | 0 | 1 |
| B   | 0 | 0 | 1 | 0 | 0 |
| C   | 0 | 0 | 0 | 1 | 0 |
| D   | 1 | 1 | 0 | 0 | 0 |
| E   | 0 | 0 | 1 | 0 | 0 |

由矩阵定义可直接看出：无向图中第 i 行（第 i 列）非零元素的个数等于顶点 i 的度；有向图中第 i 行非零元素的个数等于顶点 i 的出度，第 i 列非零元素的个数等于顶点 i 的入度。

**邻接矩阵的类型定义**
```c
typedef struct ArcCell {            // 弧的定义
    VRType   adj;                   // VRType 是顶点关系类型。
                                    // 对无权图，用 1 或 0 表示相邻否；
                                    // 对带权图，则为权值类型。
    InfoType *info;                 // 该弧相关信息的指针
} ArcCell, AdjMatrix[MAX_VERTEX_NUM][MAX_VERTEX_NUM];

typedef struct {                        // 图的定义
    VertexType  vexs[MAX_VERTEX_NUM];   // 顶点信息
    AdjMatrix   arcs;                   // 弧的信息
    int         vexnum, arcnum;         // 顶点数，弧数
    GraphKind   kind;                   // 图的种类标志
} MGraph;
```
**建立图的存储结构（`CreatGraph` 的实现要点）**：用邻接矩阵构造图时，先读入顶点集 V，把各顶点信息存入 `vexs[]`，同时置 `vexnum`；再读入弧集 VR，对每条弧 `<v,w>` 用 `LocateVex` 求出 v、w 在顶点表中的下标 i、j，置 `arcs[i][j].adj`（若为无向图，同时置 `arcs[j][i].adj` 及相应 `info`）；最后置 `arcnum` 与 `kind`。

### 二、图的邻接表存储表示

> 课件页码：P26–P31

**基本思想**：对图中每个顶点建立一个单链表，链表中的每个结点（弧结点）存放依附于该顶点的一条弧（边）的另一端点在顶点表中的下标；全部链表的头结点（顶点结点）用数组顺序存放，构成顶点表。

**例（无向图的邻接表，课件 P26）**

![无向图及其邻接表](assets/第07章图/p026.jpg)

*图 7-5 无向图及其邻接表：顶点表 + 各顶点的单链表（课件 P26）*

| 下标 | 顶点 | 邻接点序列（顶点下标） |
|---|---|---|
| 0 | A | 1 → 4 |
| 1 | B | 0 → 4 → 5 |
| 2 | C | 3 → 5 |
| 3 | D | 2 → 5 |
| 4 | E | 0 → 1 |
| 5 | F | 1 → 2 → 3 |

**结点结构**

- 弧的结点结构：`adjvex | nextarc | info`
- 顶点的结点结构：`data | firstarc`

**邻接表的类型定义**
```c
typedef struct ArcNode {
    int             adjvex;     // 该弧所指向的顶点的位置
    struct ArcNode *nextarc;    // 指向下一条弧的指针
    InfoType       *info;       // 该弧相关信息的指针
} ArcNode;

typedef struct VNode {
    VertexType  data;           // 顶点信息
    ArcNode    *firstarc;       // 指向第一条依附该顶点的弧
} VNode, AdjList[MAX_VERTEX_NUM];

typedef struct {
    AdjList  vertices;
    int      vexnum, arcnum;
    int      kind;              // 图的种类标志
} ALGraph;
```
**例（有向图的邻接表，课件 P27）**

在有向图的邻接表中，顶点 v 的链表里链接的是以 v 为弧尾的弧（即从 v 出发的弧），因此便于求出度；但**不易找到指向某顶点的弧**（求入度须扫描整个邻接表）。

**例（有向图的逆邻接表，课件 P28）**

在有向图的逆邻接表中，对每个顶点，链接的是指向该顶点的弧，因此便于求入度。

课件 P27、P28 所给有向图（顶点 A~E）的邻接表与逆邻接表对照如下：

| 顶点 | 邻接表中的邻接点序列 | 逆邻接表中的邻接点序列 |
|---|---|---|
| A（0） | 1(B) → 4(E) | 3(D) |
| B（1） | 2(C) | 0(A) → 3(D) |
| C（2） | 3(D) | 1(B) → 4(E) |
| D（3） | 0(A) → 1(B) | 2(C) |
| E（4） | 2(C) | 0(A) |

**说明**

- 无向图的邻接表把同一条边在两端点各自的链表中各存一个弧结点，共需 2e 个弧结点；有向图的邻接表（或逆邻接表）只需 e 个弧结点。
- 邻接表便于按顶点遍历其邻接点，`FirstAdjVex`、`NextAdjVex` 正是沿链表取“第一个邻接点”和“下一个邻接点”，7.3 节的深度优先、广度优先遍历都建立在这两个操作之上。

### 三、有向图的十字链表存储表示

> 课件页码：P32–P34

**基本思想**：十字链表可看作邻接表与逆邻接表的结合。每个弧结点同时被组织进两个链表：`tlink` 链接“弧尾相同”的下一条弧，`hlink` 链接“弧头相同”的下一条弧；每个顶点结点设两条链，`firstin` 指向第一条入弧，`firstout` 指向第一条出弧。

**弧的结点结构**：弧尾顶点位置 | 弧头顶点位置 | 弧的相关信息 | 指向下一个有相同弧尾的结点 | 指向下一个有相同弧头的结点

| 域名 | 含义 |
|---|---|
| `tailvex` | 弧尾顶点位置 |
| `headvex` | 弧头顶点位置 |
| `info` | 弧的相关信息 |
| `hlink` | 指向下一个有相同弧头的结点 |
| `tlink` | 指向下一个有相同弧尾的结点 |

**顶点的结点结构**：顶点信息数据 | 指向该顶点的第一条入弧 | 指向该顶点的第一条出弧
```c
typedef struct ArcBox {                 // 弧的结构表示
    int             tailvex, headvex;   // 弧尾顶点位置、弧头顶点位置
    InfoType       *info;               // 弧的相关信息
    struct ArcBox  *hlink, *tlink;
            // hlink 指向下一个有相同弧头的结点
            // tlink 指向下一个有相同弧尾的结点
} ArcBox;

typedef struct VexNode {                // 顶点的结构表示
    VertexType  data;                   // 顶点信息数据
    ArcBox     *firstin, *firstout;     // 指向该顶点的第一条入弧、第一条出弧
} VexNode;

typedef struct {
    VexNode  xlist[MAX_VERTEX_NUM];     // 顶点结点（表头向量）
    int      vexnum, arcnum;            // 有向图的当前顶点数和弧数
} OLGraph;
```

### 四、无向图的邻接多重表存储表示

> 课件页码：P35–P36

**基本思想**：邻接多重表用于无向图：每条边只用一个边结点表示，边结点记录该边依附的两个顶点位置，并分别用 `ilink`、`jlink` 链接依附这两个顶点的下一条边；顶点结点只存一个指向“第一条依附该顶点的边”的指针。这样无向图中同一条边只需存一次，并带访问标记，便于对边进行遍历、插入、删除等操作。

**边的结构表示**
```c
typedef struct EBox {
    VisitIf      mark;          // 访问标记
    int          ivex, jvex;    // 该边依附的两个顶点的位置
    struct EBox *ilink, *jlink; // 分别指向依附这两个顶点的下一条边
    InfoType    *info;          // 该边信息指针
} EBox;

typedef struct VexBox {
    VertexType  data;
    EBox       *firstedge;      // 指向第一条依附该顶点的边
} VexBox;

typedef struct {                    // 邻接多重表
    VexBox  adjmulist[MAX_VERTEX_NUM];
    int     vexnum, edgenum;
} AMLGraph;
```
### 五、四种存储表示小结

> 课件页码：P21–P36

| 存储表示 | 适用对象 | 主要结构 | 特点 |
|---|---|---|---|
| 数组（邻接矩阵） | 有向图、无向图、带权网 | 二维数组 `arcs[n][n]` | 无向图矩阵对称，有向图非对称；判两顶点是否相邻方便 |
| 邻接表 | 有向图、无向图、带权网 | 顶点表 + 弧结点单链表 | 易求出度；有向图求入度不便，需再建逆邻接表；无向图每条边存两个弧结点 |
| 十字链表 | 有向图 | 弧结点 `tailvex/headvex/hlink/tlink`；顶点结点 `firstin/firstout` | 出弧、入弧都易查，出度入度都易求 |
| 邻接多重表 | 无向图 | 边结点 `ivex/jvex/ilink/jlink`；顶点结点 `firstedge` | 每条边只存一次，便于对边操作 |

## 7.3 图的遍历

> 课件页码：P37–P57

**定义**：从图中某个顶点出发游历图，访遍图中其余顶点，并且使图中的每个顶点仅被访问一次的过程。课件 P37 分三部分：深度优先搜索、广度优先搜索、遍历应用举例。

### 一、深度优先搜索遍历图

> 课件页码：P38–P44

**连通图的深度优先搜索遍历**：从图中某个顶点 V0 出发，访问此顶点，然后依次从 V0 的各个未被访问的邻接点出发深度优先搜索遍历图，直至图中所有和 V0 有路径相通的顶点都被访问到。

课件 P39 的图解：V 的邻接点为 W1、W2、W3，SG1、SG2、SG3 分别为含顶点 W1、W2、W3 的子图。访问顶点 V 后，对 W1、W2、W3 依次判断：若该邻接点 W 未被访问，则从它出发进行深度优先搜索遍历。

由 P39 的图解可见：① 从深度优先搜索遍历连通图的过程类似于树的先根遍历；② 判别 V 的邻接点是否被访问的办法是：为每个顶点设立一个“访问标志 visited[w]”。

**算法 7.1 深度优先搜索（连通图）**
```c
void DFS(Graph G, int v) {
    // 从顶点 v 出发，深度优先搜索遍历连通图 G
    visited[v] = TRUE;  VisitFunc(v);
    for (w = FirstAdjVex(G, v); w != 0; w = NextAdjVex(G, v, w))
        if (!visited[w])  DFS(G, w);
                // 对 v 的尚未访问的邻接顶点 w 递归调用 DFS
}
```
**非连通图的深度优先搜索遍历**：先将图中每个顶点的访问标志设为 FALSE，之后搜索图中每个顶点——如果未被访问，则以该顶点为起始点进行深度优先搜索遍历，否则继续检查下一顶点。

**算法 7.2 深度优先遍历（非连通图）**
```c
void DFSTraverse(Graph G, Status (*Visit)(int v)) {
    // 对图 G 作深度优先遍历
    VisitFunc = Visit;
    for (v = 0; v < G.vexnum; ++v)
        visited[v] = FALSE;             // 访问标志数组初始化
    for (v = 0; v < G.vexnum; ++v)
        if (!visited[v])  DFS(G, v);
                // 对尚未访问的顶点调用 DFS
}
```

*图 7-6 深度优先遍历示例：访问标志数组与访问次序 a c h d k f e b g（课件 P44）*

对课件 P44 的图（顶点 a、b、c、d、e、f、g、h、k）从顶点 a 出发、按邻接表中邻接点的顺序进行深度优先搜索，得访问次序

遍历开始时访问标志数组各分量均为 FALSE，遍历结束后全部变为 TRUE；遍历过程中经过的边构成深度优先生成树。若图不连通，则对每个尚未访问的顶点都要重新启动一次 DFS，从而得到生成森林。

### 二、广度优先搜索遍历图

> 课件页码：P45–P48

**基本思想**

从图中的某个顶点 V0 出发，并在访问此顶点之后依次访问 V0 的所有未被访问过的邻接点，之后按这些顶点被访问的先后次序依次访问它们的邻接点，直至图中所有和 V0 有路径相通的顶点都被访问到。

若此时图中尚有顶点未被访问，则另选图中一个未曾被访问的顶点作起始点，重复上述过程，直至图中所有顶点都被访问到。

课件 P45 的图示：对连通图，从起始点 V 到其余各顶点必定存在路径，其中

| 路径长度 | 顶点 |
|---|---|
| 1 | w1、w2、w8 |
| 2 | w7、w3、w5 |
| 3 | w6、w4 |

![广度优先搜索分层](assets/第07章图/p045.jpg)

*图 7-7 广度优先搜索：从 V 到各顶点的路径长度按层递增（课件 P45）*

可见广度优先搜索是按“路径长度”由短到长逐层向外扩展的。

**算法 7.3 广度优先搜索遍历（以辅助队列实现）**
```c
void BFSTraverse(Graph G, Status (*Visit)(int v)) {
    for (v = 0; v < G.vexnum; ++v)
        visited[v] = FALSE;             // 初始化访问标志
    InitQueue(Q);                       // 置空的辅助队列 Q
    for (v = 0; v < G.vexnum; ++v)
        if (!visited[v]) {              // v 尚未访问
            visited[v] = TRUE;  Visit(v);       // 访问 v
            EnQueue(Q, v);                      // v 入队列
            while (!QueueEmpty(Q)) {
                DeQueue(Q, u);                  // 队头元素出队并置为 u
                for (w = FirstAdjVex(G, u); w != 0;
                     w = NextAdjVex(G, u, w))
                    if (!visited[w]) {
                        visited[w] = TRUE;  Visit(w);
                        EnQueue(Q, w);          // 访问的顶点 w 入队列
                    } // if
            } // while
        }
} // BFSTraverse
```
与 DFS 一样，`BFSTraverse` 通过外层循环处理非连通图：每个顶点至多入队一次，每条边（弧）至多被检查一次。采用邻接表存储时，两种遍历的时间复杂度均为 O(n+e)；采用邻接矩阵时为 O(n²)。

### 三、遍历应用举例

> 课件页码：P49–P57

课件 P49 给出两个遍历应用的例子：求一条从顶点 i 到顶点 s 的简单路径；求两个顶点之间的一条路径长度最短的路径。

**1. 求一条从顶点 i 到顶点 s 的简单路径**

**例（课件 P50）** 求从顶点 b 到顶点 k 的一条简单路径。从顶点 b 出发进行深度优先搜索遍历：

- 假设找到的第一个邻接点是 a，则得到的结点访问序列为：`b a d h c e k f g`；
- 假设找到的第一个邻接点是 c，则得到的结点访问序列为：`b c h d a e k f g`。

**结论（课件 P51）**

1. 从顶点 i 到顶点 s，若存在路径，则从顶点 i 出发进行深度优先搜索，必能搜索到顶点 s；
2. 遍历过程中搜索到的顶点不一定是路径上的顶点；
3. 由它出发进行的深度优先遍历已经完成的顶点不是路径上的顶点。

**算法 7.4 求一条从 v 到 s 的简单路径**
```c
void DFSearch(int v, int s, char *PATH) {
    // 从第 v 个顶点出发递归地深度优先遍历图 G，
    // 求得一条从 v 到 s 的简单路径，并记录在 PATH 中
    visited[v] = TRUE;              // 访问第 v 个顶点
    Append(PATH, getVertex(v));     // 第 v 个顶点加入路径
    for (w = FirstAdjVex(v); w != 0 && !found; w = NextAdjVex(v))
        if (w == s) { found = TRUE;  Append(PATH, w); }
        else  if (!visited[w])  DFSearch(w, s, PATH);
    if (!found)  Delete(PATH);      // 从路径上删除顶点 v
}
```
算法要点：用 PATH 记录当前搜索路径，进入顶点时加入、回溯（`found` 为假）时删除，因此 PATH 中始终是“当前路径”上的顶点；一旦 `found` 为真，递归逐层返回时不再删除，PATH 即为所求简单路径。

**2. 求两个顶点之间的一条路径长度最短的路径**

**问题（课件 P53）**：若两个顶点之间存在多条路径，则其中必有一条路径长度最短的路径。如何求得这条路径？

**思路（课件 P54）**：深度优先搜索访问顶点的次序取决于图的存储结构，而广度优先搜索访问顶点的次序是按“路径长度”渐增的次序。因此，求路径长度最短的路径可以基于广度优先搜索遍历进行，但需要修改链队列的结点结构及其入队列和出队列的算法。

**例（课件 P55）**：求下图中顶点 3 至顶点 5 的一条最短路径，链队列的状态如下所示：队列中依次存放 `3 → 1 → 2 → 4 → 7 → 5 …`，`Q.front` 指向当前队头，`Q.rear` 指向队尾。

**修改方法（课件 P56）**

1. 将链队列的结点改为“双链”结点，即结点中包含 `next` 和 `priou` 两个指针；
2. 修改入队列的操作。插入新的队尾结点时，令其 `priou` 域的指针指向刚刚出队列的结点，即当前的队头指针所指结点；
3. 修改出队列的操作。出队列时，仅移动队头指针（不释放结点）。

这样，队列中每个结点都通过 `priou` 记录了“它是从哪个顶点被发现的”；由于 BFS 按路径长度渐增的次序访问顶点，第一次访问到终点时，沿 `priou` 指针从终点回溯到起点即得一条最短路径。

**算法 7.5 修改后的链队列操作**
```c
typedef  DuLinkList QueuePtr;

void InitQueue(LinkQueue &Q) {
    Q.front = Q.rear = (QueuePtr)malloc(sizeof(QNode));
    Q.front->next = Q.rear->next = NULL;
}

void EnQueue(LinkQueue &Q, QelemType e) {
    p = (QueuePtr) malloc(sizeof(QNode));
    p->data = e;  p->next = NULL;
    p->priou = Q.front;             // 指向刚刚出队列的结点
    Q.rear->next = p;  Q.rear = p;
}

void DeQueue(LinkQueue &Q, QelemType &e) {
    Q.front = Q.front->next;        // 仅移动队头指针，不释放结点
    e = Q.front->data;
}
```

## 7.4 （连通网的）最小生成树

> 课件页码：P58–P70

### 一、问题的提出

> 课件页码：P58–P59

**问题**：假设要在 n 个城市之间建立通讯联络网，则连通 n 个城市只需要修建 n−1 条线路，如何在最节省经费的前提下建立这个通讯网？

**等价问题**：构造网的一棵最小生成树，即：在 e 条带权的边中选取 n−1 条边（不构成回路），使“权值之和”为最小。课件 P59 给出求解该问题的两种算法：算法一（普里姆算法）、算法二（克鲁斯卡尔算法）。

### 二、普里姆（Prim）算法

> 课件页码：P60–P66

**基本思想（P60）**：取图中任意一个顶点 v 作为生成树的根，之后往生成树上添加新的顶点 w。在添加的顶点 w 和已经在生成树上的顶点 v 之间必定存在一条边，并且该边的权值在所有连通顶点 v 和 w 之间的边中取值最小。之后继续往生成树上添加顶点，直至生成树上含有 n 个顶点（即 n−1 条边）为止。

**例（P61）**：以 7 个顶点 a~g 的带权无向网为例（边权 ab=19、ae=14、ag=18、be=12、bc=5、bd=7、ed=8、eg=16、gf=27、df=21、dc=3），从顶点 a 出发，每次把“与当前生成树距离最近的顶点”及其边加入生成树，最终得到最小生成树（课件 P61 分别给出原网与所得生成树，权值和 14+8+3+5+16+21=67）。

![普里姆算法示例](assets/第07章图/p061.jpg)

*图 7-8 普里姆算法示例：所得生成树权值和 14+8+3+5+16+21 = 67（课件 P61）*

**一般情况下所添加的顶点应满足的条件（P62）**：在生成树的构造过程中，图中 n 个顶点分属两个集合：已落在生成树上的顶点集 U 和尚未落在生成树上的顶点集 V−U，则应在所有连通 U 中顶点和 V−U 中顶点的边中选取权值最小的边。

**辅助数组（P63）**：对当前 V−U 集中的每个顶点，记录和顶点集 U 中顶点相连接的代价最小的边：
```c
struct {
    VertexType  adjvex;     // U 集中的顶点序号
    VRType      lowcost;    // 边的权值
} closedge[MAX_VERTEX_NUM];
```

![closedge 数组](assets/第07章图/p064.jpg)

*图 7-9 closedge 数组各分量的 Adjvex 与 Lowcost 取值（课件 P64）*

**closedge 的更新过程（P64）**：课件 P64 的表格按列给出各顶点（0~6）的 Adjvex 行与 Lowcost 行，记录了辅助数组在初始状态以及每次并入新顶点后的取值变化（如表中 closedge[b]={c,5}、closedge[f]={d,21}）。每次迭代分三步：

1. 在 `closedge` 中求 `lowcost` 最小的分量，其对应顶点 k 即“下一个加入生成树的顶点”；
2. 输出边 `(closedge[k].adjvex, k)`，并令 `closedge[k].lowcost = 0`，表示顶点 k 并入 U 集；
3. 以顶点 k 为“新起点”修改其余顶点的最小边：对每个 j∈V−U，若 `G.arcs[k][j].adj < closedge[j].lowcost`，则令 `closedge[j] = {G.vexs[k], G.arcs[k][j].adj}`。

**算法 7.6 普里姆算法**
```c
void MiniSpanTree_P(MGraph G, VertexType u) {
    // 用普里姆算法从顶点 u 出发构造网 G 的最小生成树
    k = LocateVex(G, u);
    for (j = 0; j < G.vexnum; ++j)          // 辅助数组初始化
        if (j != k)
            closedge[j] = { u, G.arcs[k][j].adj };
    closedge[k].lowcost = 0;                // 初始，U＝{u}
    for (i = 0; i < G.vexnum; ++i) {
        k = minimum(closedge);              // 求出加入生成树的下一个顶点 k
        printf(closedge[k].adjvex, G.vexs[k]);
                                            // 输出生成树上一条边
        closedge[k].lowcost = 0;            // 第 k 顶点并入 U 集
        for (j = 0; j < G.vexnum; ++j)      // 修改其它顶点的最小边
            if (G.arcs[k][j].adj < closedge[j].lowcost)
                closedge[j] = { G.vexs[k], G.arcs[k][j].adj };
    }
}
```
**算法分析**：每次从 `closedge` 中选最小值的代价为 O(n)，共进行 n 次，故时间复杂度为 **O(n²)**，与网中的边数无关，适用于稠密图（见 P70 的比较表）。

### 三、克鲁斯卡尔（Kruskal）算法

> 课件页码：P67–P69

**基本思想（P67）**

- 具体做法：先构造一个只含 n 个顶点的子图 SG，然后从权值最小的边开始，若它的添加不使 SG 中产生回路，则在 SG 上加上这条边，如此重复，直至加上 n−1 条边为止。
- 考虑问题的出发点：为使生成树上边的权值之和达到最小，则应使生成树中每一条边的权值尽可能地小。

**例（P68）**：对 P61 中的同一个带权网，按边权从小到大逐条考察，加入不产生回路的边，直到选够 n−1 条边，所得最小生成树与 Prim 算法的结果一致（选入 ae=14、ed=8、dc=3、bc=5、eg=16、df=21）。

![克鲁斯卡尔算法示例](assets/第07章图/p068.jpg)

*图 7-10 克鲁斯卡尔算法示例：按权值递增选入不使 SG 产生回路的边（课件 P68）*

**算法描述（P69）**
```text
构造非连通图 ST = (V, { });
k = i = 0;                      // k 计选中的边数
while (k < n-1) {
    ++i;
    检查边集 E 中第 i 条权值最小的边 (u,v);
    若 (u,v) 加入 ST 后不使 ST 中产生回路，
    则  输出边 (u,v);  且  k++;
}
```
**实现要点**：先把全部边按权值从小到大排序；判断“加入一条边后是否产生回路”可借助并查集 MFSet（第 6.5 节）：并查集中每个集合是当前已连通的一个顶点集合，若边 (u,v) 的两端点属于不同集合，则加入该边不会成回路，加入后用 Union 合并两个集合。

> 说明：课件仅给出算法描述，以下 C 实现（借助并查集 MFSet 判回路）为教材配套参考实现。

```c
typedef struct {
    int     u, v;       // 边的两个顶点
    VRType  w;          // 权值
} Edge;

int Find(int x) {                       // 并查集查找，返回所在集合的代表元
    while (x != MFSet[x])  x = MFSet[x];
    return x;
}

void Union(int a, int b) {              // 合并两个集合
    MFSet[a] = b;
}

void MiniSpanTree_K(Edge edges[], int e, int n) {
    // 按课件 P69 的算法描述实现：从权值最小的边开始选边
    Sort(edges, e);                     // 将边集按权值从小到大排序
    for (i = 0; i < n; ++i)  MFSet[i] = i;  // 并查集初始化
    k = 0;                              // k 计选中的边数
    for (i = 0; i < e && k < n - 1; ++i) {
        ru = Find(edges[i].u);
        rv = Find(edges[i].v);
        if (ru != rv) {                 // 两端点不在同一集合，加入后不产生回路
            Union(ru, rv);
            printf(edges[i].u, edges[i].v, edges[i].w);   // 输出边
            ++k;
        }
    }
}
```
**算法分析**：时间主要花在对 e 条边的排序上，故时间复杂度为 **O(e log e)**，与顶点数关系较小，适用于稀疏图。

## 7.5 重（双）连通图和关节点

> 课件页码：P71–P81

### 一、问题的提出

> 课件页码：P71–P72

- **重（双）连通图**：若从一个连通图中删去任何一个顶点及其相关联的边，它仍为一个连通图的话，则该连通图被称为重（双）连通图。
- **关节点**：若连通图中的某个顶点和其相关联的边被删去之后，该连通图被分割成两个或两个以上的连通分量，则称此顶点为关节点。
- 没有关节点的连通图为双连通图。问题：如何判别给定的连通图是否是双连通图？

**分析依据（P74）**：假设从某个顶点 V0 出发对连通图进行深度优先搜索遍历，则可得到一棵深度优先生成树，树上包含图的所有顶点，因此需借助图的深度优先生成树来分析关节点的特征。

**判定准则（P75）**

1. 若生成树的根结点有两个或两个以上的分支，则此顶点（生成树的根）必为关节点；
2. 对生成树上的任意一个“顶点”，若其某棵子树的根或子树中的其它“顶点”没有和其祖先相通的回边，则该顶点为关节点。

问题（P76）：对上述两个判定准则在算法中如何实现？

### 三、low 函数与算法实现

> 课件页码：P77–P81

**1）设 V0 为深度优先遍历的出发点**
```c
p = G.vertices[0].firstarc;  v = p->adjvex;
DFSArticul(G, v);                   // 从第 v 顶点出发深度优先搜索
if (count < G.vexnum) {             // 生成树的根有至少两棵子树
    printf(0, G.vertices[0].data);  // 根是关节点，输出
}
```
**2）定义函数**

    low(v) = Min{ visited[v], low[w], visited[k] }

其中：顶点 w 是生成树上顶点 v 的孩子；顶点 k 是生成树上和顶点 v 由回边相联接的祖先；visited 记录深度优先遍历时的访问次序。

若对顶点 v，在生成树上存在一个子树根 w，且

    low[w] ≥ visited[v]

则顶点 v 为关节点。

**3）对深度优先遍历算法作如下修改（P79）**

1. `visited[v]` 的值改为遍历过程中顶点的访问次序 count 值；
2. 遍历过程中求得 `low[v] = Min{visited[v], low[w], visited[k]}`；
3. 从子树遍历返回时，用子树根的 `low[w]` 修正 `low[v]`，并按 `low[w] ≥ visited[v]` 判定 v 是否为关节点。

**算法 7.7 查找并输出连通图的全部关节点**
```c
void FindArticul(ALGraph G) {
    // 连通图 G 以邻接表作存储结构，查找并输出 G 上全部关节点
    count = 1;  visited[0] = 1;         // 设 0 号顶点为生成树的根
    for (i = 1; i < G.vexnum; ++i)  visited[i] = 0;  // 其余顶点尚未访问
    p = G.vertices[0].firstarc;  v = p->adjvex;
    DFSArticul(G, v);                   // 从第 v 顶点出发深度优先查找关节点
    if (count < G.vexnum) {             // 生成树的根有至少两棵子树
        printf(0, G.vertices[0].data);  // 0 号顶点是关节点
        while (p->nextarc) {            // 对其余子树的根分别处理
            p = p->nextarc;  v = p->adjvex;
            if (visited[v] == 0)  DFSArticul(G, v);
        }
    }
}

void DFSArticul(ALGraph G, int v0) {
    // 从第 v0 个顶点出发深度优先遍历图 G，查找并输出关节点
    min = visited[v0] = ++count;
        // v0 是第 count 个访问的顶点，并设 low[v0] 的初值为 min
    for (p = G.vertices[v0].firstarc; p; p = p->nextarc) {
        w = p->adjvex;                      // w 为 v0 的邻接顶点
        if (visited[w] == 0) {              // w 未曾被访问
            DFSArticul(G, w);               // 返回前求得 low[w]
            if (low[w] < min)  min = low[w];
            if (low[w] >= visited[v0])
                printf(v0, G.vertices[v0].data);   // 输出关节点
        }
        else if (visited[w] < min)  min = visited[w];
                    // w 是回边上的顶点，用其访问次序修正 min
    }
    low[v0] = min;                          // 从子树遍历返回时求得 low[v0]
}
```
**说明**：`DFSArticul` 在深度优先遍历的同时求 `low[v0]`（取 visited[v0]、各子树根的 low 值、回边所连祖先的 visited 值三者最小），并在每次从子树返回时用 `low[w] ≥ visited[v0]` 判定 v0 是否为关节点。整个过程对每个顶点、每条边各处理一次，采用邻接表存储时时间复杂度为 O(n+e)。

## 7.6 两点之间的最短路径问题

> 课件页码：P82–P89

课件 P82 列出两类问题：

- 求从某个源点到其余各点的最短路径
- 每一对顶点之间的最短路径

### 一、从某个源点到其余各点的最短路径（迪杰斯特拉算法）

> 课件页码：P83–P87

**基本思想（P83）**：依最短路径的长度递增的次序求得各条路径。其中，从源点到顶点 v 的最短路径是所有最短路径中长度最短者。

![迪杰斯特拉算法基本思想](assets/第07章图/p083.jpg)

*图 7-12 迪杰斯特拉算法：按最短路径长度递增的次序逐条求得（课件 P83）*

**各条最短路径的特点（P84–P85）**

| 次序 | 路径特点 |
|---|---|
| 第 1 条（最短） | 必定只含一条弧，并且这条弧的权值最小 |
| 第 2 条（次短） | 只可能有两种情况：或者是直接从源点到该点（只含一条弧）；或者是从源点经过顶点 v1，再到达该顶点（由两条弧组成） |
| 第 3 条 | 可能有三种情况：直接从源点到该点（只含一条弧）；从源点经过 v1 再到达该顶点；从源点经过 v2 再到达该顶点 |
| 其余各条 | 或者是直接从源点到该点（只含一条弧）；或者是从源点经过已求得最短路径的顶点，再到达该顶点 |

**辅助数组 Dist（P86）**：设置辅助数组 Dist，其中每个分量 Dist[k] 表示当前所求得的从源点到其余各顶点 k 的最短路径。一般情况下，

    Dist[k] = <源点到顶点 k 的弧上的权值>
    或者   = <源点到其它顶点的路径长度> + <其它顶点到顶点 k 的弧上的权值>

**算法步骤（P87）**

1. 在所有从源点出发的弧中选取一条权值最小的弧，即为第一条最短路径；
2. 修改其它各顶点的 Dist[k] 值。假设求得最短路径的顶点为 u，若 `Dist[u] + G.arcs[u][k] < Dist[k]`，则将 `Dist[k]` 改为 `Dist[u] + G.arcs[u][k]`；
3. 其中的最小值即为最短路径的长度。

Dist 的初值（v0 为源点）：

    Dist[k] = G.arcs[v0][k].adj     v0 和 k 之间存在弧
    Dist[k] = INFINITY              v0 和 k 之间不存在弧

**算法 7.8 迪杰斯特拉算法**

> 说明：课件仅给出算法思想与递推关系，以下 C 实现为教材配套参考实现。

```c
void ShortestPath_DIJ(MGraph G, int v0, PathMatrix &P, ShortPathTable &D) {
    // 用迪杰斯特拉算法求有向网 G 的 v0 顶点到其余顶点 v 的最短路径 P[v]
    // 及其带权长度 D[v]。若 P[v][w] 为 TRUE，则 w 是 v0 到 v 当前最短路径上的顶点
    for (v = 0; v < G.vexnum; ++v) {            // 初始化
        final[v] = FALSE;
        D[v] = G.arcs[v0][v].adj;
        for (w = 0; w < G.vexnum; ++w)  P[v][w] = FALSE;
        if (D[v] < INFINITY) { P[v][v0] = TRUE;  P[v][v] = TRUE; }
    }
    D[v0] = 0;  final[v0] = TRUE;               // v0 并入已求出最短路径的顶点集
    for (i = 1; i < G.vexnum; ++i) {            // 对其余 vexnum-1 个顶点
        min = INFINITY;
        for (w = 0; w < G.vexnum; ++w)
            if (!final[w] && D[w] < min) { v = w;  min = D[w]; }
        final[v] = TRUE;                        // 当前 Dist 最小者并入集合
        for (w = 0; w < G.vexnum; ++w)          // 修改其它顶点的 Dist 值
            if (!final[w] && (min + G.arcs[v][w].adj < D[w])) {
                D[w] = min + G.arcs[v][w].adj;
                P[w] = P[v];  P[w][w] = TRUE;
            }
    }
}
```
**示例推演（按课件 P83–P85 的分析顺序）**

1. 初始时已求出最短路径的顶点集 S 中只有源点 v0，Dist[k] 为 v0 到 k 的直接弧权值（无弧则取 ∞）；
2. 从 V−S 中取 Dist 最小的顶点 v1，则 v0→v1 即第一条最短路径；把 v1 并入 S，按 `Dist[v1] + arcs[v1][k] < Dist[k]` 修正其余各点的 Dist；
3. 再从 V−S 中取 Dist 最小者 v2：它的最短路径只可能是“直达”或“经 v1”，与 P84 的分析一致；并入 S 后继续修正；
4. 重复上述过程，直至所有顶点都并入 S，即按路径长度递增的次序依次求得源点到其余各点的最短路径。

**算法分析**：共进行 n−1 轮，每轮选最小 Dist 需 O(n)、修改 Dist 需 O(n)，故时间复杂度为 **O(n²)**。

### 二、每一对顶点之间的最短路径（弗洛伊德算法）

> 课件页码：P88–P89

**基本思想（P88）**：弗洛伊德算法的基本思想是，从 vi 到 vj 的所有可能存在的路径中，选出一条长度最短的路径。

![弗洛伊德算法的基本思想](assets/第07章图/p088.jpg)

*图 7-13 弗洛伊德算法的基本思想：从 vi 到 vj 的所有可能路径中选最短者（课件 P88）*

**路径的逐步扩充（P89）**

- 若 `<vi,vj>` 存在，则存在路径 {vi, vj}（路径中不含其它顶点）；
- 若 `<vi,v1>`、`<v1,vj>` 存在，则存在路径 {vi, v1, vj}（路径中所含顶点序号不大于 1）；
- 若 {vi,…,v2}、{v2,…,vj} 存在，则存在一条路径 {vi, …, v2, …vj}（路径中所含顶点序号不大于 2）；
- 依次类推，则 vi 至 vj 的最短路径应是上述这些路径中，路径长度最小者。

**算法 7.9 弗洛伊德算法**

> 说明：课件仅给出算法思想与逐层扩充路径的思路，以下 C 实现为教材配套参考实现。

```c
void ShortestPath_FLOYD(MGraph G, PathMatrix &P[], DistancMatrix &D) {
    // 用弗洛伊德算法求有向网 G 中各对顶点 v 和 w 之间的最短路径 P[v][w]
    // 及其带权长度 D[v][w]。若 P[v][w][u] 为 TRUE，则 u 是 v 到 w 当前最短路径上的顶点
    for (v = 0; v < G.vexnum; ++v)              // 初始化各对顶点之间的已知距离
        for (w = 0; w < G.vexnum; ++w) {
            D[v][w] = G.arcs[v][w].adj;
            for (u = 0; u < G.vexnum; ++u)  P[v][w][u] = FALSE;
            if (D[v][w] < INFINITY) {           // 从 v 到 w 有直接路径
                P[v][w][v] = TRUE;  P[v][w][w] = TRUE;
            }
        }
    for (u = 0; u < G.vexnum; ++u)
        for (v = 0; v < G.vexnum; ++v)
            for (w = 0; w < G.vexnum; ++w)
                if (D[v][u] + D[u][w] < D[v][w]) {   // 从 v 经 u 到 w 的路径更短
                    D[v][w] = D[v][u] + D[u][w];
                    for (i = 0; i < G.vexnum; ++i)
                        P[v][w][i] = P[v][u][i] || P[u][w][i];
                }
}
```
**示例推演**：以邻接矩阵为 D 的初值（此时只允许“直达”），第 1 轮允许经过顶点 1 中转，第 2 轮允许经过顶点 2 中转……第 n 轮允许经过所有顶点中转。每轮只做“用 D[v][u]+D[u][w] 尝试改进 D[v][w]”的比较；可用的中间顶点逐轮增多，路径长度只会变小，故 n 轮之后 D[v][w] 即为 vi 到 vj 的最短路径长度。

**算法分析**：三重循环，时间复杂度 **O(n³)**；需要保存 D 和 P 两个 n 阶矩阵，空间复杂度 O(n²)。

### 三、拓扑排序的方法

> 课件页码：P94–P96

**进行拓扑排序的步骤（P94）**

1. 从有向图中选取一个没有前驱的顶点，并输出之；
2. 从有向图中删去此顶点以及所有以它为尾的弧；

| 定性概念 | 定量描述 |
|---|---|
| 没有前驱的顶点 | 入度为零的顶点 |
| 删除顶点及以它为尾的弧 | 弧头顶点的入度减 1 |

例如，对课件 P95 的有向图（顶点 a~h）按上述方法可依次输出 `a b h c d g f e`，得到它的一个拓扑有序序列。

**算法描述（P96）**
```text
取入度为零的顶点 v;
while (v <> 0) {
    printf(v);  ++m;
    w := FirstAdj(v);
    while (w <> 0) {
        inDegree[w]--;
        w := nextAdj(v, w);
    }
    取下一个入度为零的顶点 v;
}

```
### 四、拓扑排序的算法实现（用栈保存入度为零的顶点）

> 课件页码：P97–P98

为避免每次都要搜索入度为零的顶点，在算法中设置一个“栈”，以保存“入度为零”的顶点。
```c
CountInDegree(G, indegree);         // 对各顶点求入度
InitStack(S);
for (i = 0; i < G.vexnum; ++i)
    if (!indegree[i])  Push(S, i);  // 入度为零的顶点入栈
```
```c
count = 0;                          // 对输出顶点计数
while (!EmptyStack(S)) {
    Pop(S, v);  ++count;  printf(v);
    for (w = FirstAdj(v); w; w = NextAdj(G, v, w)) {
        --indegree(w);              // 弧头顶点的入度减一
        if (!indegree[w])  Push(S, w);
                // 新产生的入度为零的顶点入栈
    }
}
if (count < G.vexnum)  printf("图中有回路");
```
**结论**

- 若输出的顶点数 `count` 小于图的顶点数 `G.vexnum`，说明图中存在回路（图不空但找不到无前驱的顶点）；否则输出的序列即为一个拓扑有序序列。同一个有向图可能存在多个拓扑有序序列（如 P92 的 A B C D 与 A C B D）；
- 每个顶点入栈、出栈各一次，每条弧的入度各被减一次，采用邻接表存储时时间复杂度为 O(n+e)。

## 7.8 关键路径

> 课件页码：P99–P106

### 一、问题的提出

> 课件页码：P99–P100

**问题**：假设以有向网表示一个施工流图，弧上的权值表示完成该项子工程所需时间。问：哪些子工程项是“关键工程”？即：哪些子工程项将影响整个工程的完成？

**例（P100）**：课件 P100 给出一个有向网（9 个事件 a、b、c、d、e、f、g、h、k，11 项活动），其中：

- “关键活动”指的是：该弧上的权值增加将使有向图上的最长路径的长度增加；
- 整个工程完成的时间为：从有向图的源点到汇点的最长路径；
- 网中只有入度为 0 的顶点（源头事件，称为**源点**）和出度为 0 的顶点（收尾事件，称为**汇点**）各一个。

![关键路径示例 AOE 网](assets/第07章图/p100.jpg)

*图 7-17 关键路径示例的 AOE 网：源点 a、汇点 k，弧上权值为活动时间（课件 P100）*

### 二、与关键路径有关的量

> 课件页码：P101–P102

- “事件（顶点）”的**最早发生时间** ve(j) = 从源点到顶点 j 的最长路径长度；
- “事件（顶点）”的**最迟发生时间** vl(k)：在不推迟整个工程完成时间的前提下，事件 k 最迟必须发生的时间。课件 P101 表述为“从顶点 k 到汇点的最短路径长度”；按 P103 的递推式与 P104–P105 的实例数值，它等于“汇点的最早发生时间 − 从 k 到汇点的最长路径长度”；
- “活动（弧）”的**最早开始时间** ee(i) = ve(j)，**最迟开始时间** el(i) = vl(k) − dut(`<j,k>`)，其中第 i 条弧为 `<j,k>`，dut(`<j,k>`) 为该弧上的权值。

### 三、事件发生时间的计算公式

> 课件页码：P103

    ve(源点) = 0
    ve(k) = Max{ ve(j) + dut(<j,k>) }        （<j,k> 为以 k 为弧头的弧）
    vl(汇点) = ve(汇点)
    vl(k) = Min{ vl(j) − dut(<k,j>) }        （<k,j> 为以 k 为弧尾的弧）

**关键活动的判定**：算出各活动的 ee(i) 与 el(i) 后，若 ee(i)=el(i)，说明该活动没有时间余量，为关键活动；由关键活动组成的从源点到汇点的路径即为关键路径，其长度等于整个工程的完成时间。

### 四、示例推演（课件 P100、P104、P105 的有向网）

> 课件页码：P100、P104–P105

**网中的活动（弧）及其权值**

| 活动 | a→b | a→c | a→d | b→e | c→e | d→f | e→g | e→h | f→h | g→k | h→k |
|---|---|---|---|---|---|---|---|---|---|---|---|
| 权值 | 6 | 4 | 5 | 1 | 1 | 2 | 8 | 7 | 4 | 2 | 4 |

拓扑有序序列：`a d f c b e h g k`；拓扑逆序序列：`k g h e b c f d a`。

**求 ve（按拓扑有序次序）**

ve(a)=0；ve(b)=6，ve(c)=4，ve(d)=5；ve(f)=ve(d)+2=7；ve(e)=Max{ve(b)+1, ve(c)+1}=Max{7,5}=7；ve(h)=Max{ve(e)+7, ve(f)+4}=Max{14,11}=14；ve(g)=ve(e)+8=15；ve(k)=Max{ve(g)+2, ve(h)+4}=Max{17,18}=18。

**求 vl（按拓扑逆序，vl(汇点)=ve(汇点)=18）**

vl(g)=18−2=16，vl(h)=18−4=14；vl(e)=Min{vl(g)−8, vl(h)−7}=Min{8,7}=7；vl(f)=vl(h)−4=10，vl(c)=vl(e)−1=6，vl(b)=vl(e)−1=6；vl(d)=vl(f)−2=8；vl(a)=Min{vl(b)−6, vl(c)−4, vl(d)−5}=Min{0,2,3}=0。

**求 ee、el 并找出关键活动**：对每条弧 `<j,k>` 计算 ee=ve(j)、el=vl(k)−dut(<j,k>)，得

| 活动 | a→b | a→c | a→d | b→e | c→e | d→f | e→g | e→h | f→h | g→k | h→k |

### 五、算法的实现要点

> 课件页码：P106

- 求 ve 的顺序应该是按拓扑有序的次序；求 vl 的顺序应该是按拓扑逆序的次序；
- 因为拓扑逆序序列即为拓扑有序序列的逆序列，因此应该在拓扑排序的过程中，用栈保存输出的拓扑有序序列，求 vl 时再依次退栈，即得拓扑逆序次序。

**算法 7.10 求关键路径（按上述要点整理）**
```c
Status TopologicalOrder(ALGraph G, Stack &T) {
    // 有向网 G 采用邻接表存储，求各顶点事件的最早发生时间 ve
    // 若 G 无回路，则用栈 T 返回 G 的一个拓扑序列
    FindInDegree(G, indegree);                  // 对各顶点求入度
    InitStack(T);  count = 0;
    for (i = 0; i < G.vexnum; ++i)
        if (!indegree[i])  Push(T, i);
    for (i = 0; i < G.vexnum; ++i)  ve[i] = 0;  // ve 初始化
    while (!EmptyStack(T)) {
        Pop(T, j);  ++count;
        for (p = G.vertices[j].firstarc; p; p = p->nextarc) {
            k = p->adjvex;
            --indegree[k];                      // 入度减一
            if (!indegree[k])  Push(T, k);
            if (ve[j] + *(p->info) > ve[k])
                ve[k] = ve[j] + *(p->info);     // 求 ve[k]
        }
    }
    if (count < G.vexnum)  return ERROR;        // 网中有回路
    return OK;
}

Status CriticalPath(ALGraph G) {
    // 求有向网 G 的关键活动
    if (!TopologicalOrder(G, T))  return ERROR; // 求出 ve 及拓扑序列栈 T
    for (i = 0; i < G.vexnum; ++i)
        vl[i] = ve[G.vexnum-1];                 // vl 初始化
    while (!EmptyStack(T)) {                    // 按拓扑逆序求 vl
        Pop(T, j);
        for (p = G.vertices[j].firstarc; p; p = p->nextarc) {
            k = p->adjvex;
            if (vl[k] - *(p->info) < vl[j])
                vl[j] = vl[k] - *(p->info);     // 求 vl[j]
        }
    }
    for (j = 0; j < G.vexnum; ++j)              // 求 ee、el，判断关键活动
        for (p = G.vertices[j].firstarc; p; p = p->nextarc) {
            k = p->adjvex;
            ee = ve[j];                         // ee(i) = ve(j)
            el = vl[k] - *(p->info);            // el(i) = vl(k) − dut(<j,k>)
            tag = (ee == el) ? '*' : ' ';
            printf(G.vertices[j].data, G.vertices[k].data,
                   *(p->info), ee, el, tag);    // 输出活动及其 ee、el
        }
    return OK;
}
```
**算法分析**：拓扑排序求 ve 需 O(n+e)，逆拓扑序求 vl 需 O(n+e)，扫描全部弧计算 ee、el 需 O(n+e)，故采用邻接表存储时总的时间复杂度为 **O(n+e)**。

## 本章要点回顾

1. 图由顶点集 V 和弧集 VR 构成：Graph=(V, R)；`<v,w>` 表示从 v 到 w 的弧（v 为弧尾、w 为弧头），若 `<v,w>` 与 `<w,v>` 同时存在则为无向图的边；弧或边带权的图分别称为有向网或无向网。
2. 完全图：无向图 e=n(n−1)/2，有向图 e=n(n−1)；e<n log n 为稀疏图，否则为稠密图。
3. 顶点的度 TD=OD+ID；路径长度、简单路径、简单回路、连通分量、强连通分量、生成树、生成森林等概念的定义。
4. 四种存储表示：邻接矩阵（无向图对称、有向图非对称）、邻接表（易求出度，有向图求入度需逆邻接表）、十字链表（有向图，出弧入弧都易查）、邻接多重表（无向图，每条边只存一次）。
5. 深度优先搜索类似树的先根遍历，用 visited 数组作访问标志；`DFSTraverse` 通过外层循环从每个尚未访问的顶点重新启动 DFS。
6. 广度优先搜索借助队列，按“路径长度”渐增的次序逐层向外访问；`BFSTraverse` 同样用外层循环处理非连通图。
7. 遍历应用：`DFSearch` 用 PATH 记录当前路径求一条从 v 到 s 的简单路径；把链队列结点改为带 `priou` 指针的双链结点后，可基于 BFS 求得两顶点间长度最短的路径。
8. 最小生成树：Prim 每次选取 U 与 V−U 之间的最小边，O(n²)，适合稠密图；Kruskal 按权值递增逐条选边并判回路，O(e log e)，适合稀疏图。
9. 关节点：生成树的根有两个及以上分支则为关节点；其余顶点 v 若存在子树根 w 使 `low[w] ≥ visited[v]` 则为关节点，其中 low(v)=Min{visited[v], low[w], visited[k]}。
10. 迪杰斯特拉算法按路径长度递增的次序求单源最短路径，用 Dist 数组及 `Dist[u]+G.arcs[u][k] < Dist[k]` 不断松弛，时间复杂度 O(n²)。
11. 弗洛伊德算法依次以每个顶点作为中间点递推：当 `D[v][u]+D[u][w] < D[v][w]` 时更新，n 轮后得到所有顶点对的最短路径，时间复杂度 O(n³)。
12. 拓扑排序反复“输出入度为零的顶点并删除以它为尾的弧”，用栈保存入度为零的顶点；若输出顶点数小于 n 则图中有回路。关键路径中 ve 按拓扑有序次序计算、vl 按拓扑逆序计算，`ee(i)=ve(j)`、`el(i)=vl(k)−dut(<j,k>)`，ee=el 的活动为关键活动。
