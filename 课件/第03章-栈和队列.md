## 章首导言

> 课件页码：P1–P2

通常称，**栈和队列**是限定插入和删除只能在表的“端点”进行的线性表。它们仍是线性表，只是把插入、删除的位置限制在表的端点，因而成为两种最常用的数据类型。它们与一般线性表的对比如下：

| 操作 | 线性表 L | 栈 S | 队列 Q |
| --- | --- | --- | --- |
| 插入 | `Insert(L, i, x)`，`1 ≤ i ≤ n+1`（可插入任意位置） | `Insert(S, n+1, x)`（只在表尾插入） | `Insert(Q, n+1, x)`（只在表尾插入） |
| 删除 | `Delete(L, i)`，`1 ≤ i ≤ n`（可删除任意元素） | `Delete(S, n)`（只删除表尾元素） | `Delete(Q, 1)`（只删除表头元素） |

- 栈：插入和删除都只在表的同一端（表尾，即栈顶）进行，后进先出；队列：插入在表尾（队尾）进行、删除在表头（队头）进行，先进先出。

### 三、基本操作的初始条件与操作结果

> 课件页码：P5–P11

| 操作 | 初始条件 | 操作结果 |
| --- | --- | --- |
| `InitStack(&S)` | — | 构造一个空栈 S |
| `DestroyStack(&S)` | 栈 S 已存在 | 栈 S 被销毁 |
| `ClearStack(&S)` | 栈 S 已存在 | 将 S 清为空栈 |
| `StackEmpty(S)` | 栈 S 已存在 | 若栈 S 为空栈则返回 TRUE，否则返回 FALSE |
| `StackLength(S)` | 栈 S 已存在 | 返回 S 的元素个数，即栈的长度 |
| `GetTop(S, &e)` | 栈 S 已存在且非空 | 用 e 返回 S 的栈顶元素 |
| `Push(&S, e)` | 栈 S 已存在 | 插入元素 e 为新的栈顶元素 |
| `Pop(&S, &e)` | 栈 S 已存在且非空 | 删除 S 的栈顶元素，并用 e 返回其值 |

**取栈顶元素**：`GetTop(S, &e)` 只读取栈顶元素的值，不改变栈的内容。课件 P8 的图示中，栈顶指针（图中箭头）指向 a_n：

![GetTop 操作：用 e 返回栈顶元素 an](assets/第03章栈和队列/p008.jpg)

*图 3-1 GetTop 操作：用 e 返回栈顶元素 a_n（课件 P8）*

**进栈**：`Push(&S, e)` 在栈顶插入元素 e，e 成为新的栈顶元素。课件 P10 的图示中，e 被插在 a_n 之后：

![Push 操作：元素 e 入栈后成为新的栈顶](assets/第03章栈和队列/p010.jpg)

*图 3-2 Push 操作：插入元素 e 后 e 成为新的栈顶（课件 P10）*

**出栈**：`Pop(&S, &e)` 与 Push 互为逆操作——先删除栈顶元素 a_n，并用 e 返回其值，栈顶指针随之下移一个位置。因此栈的操作具有“后进先出”的特点。

### 例一、数制转换

> 课件页码：P13–P15

**问题**：把十进制整数 N 转换为 d 进制数输出（课件以 d = 8 为例）。

**算法基于原理**：

```
N = (N div d) × d + N mod d
```

**算法思想**：

- `N mod d` 得到的是 d 进制数的最低位，`N div d` 是余下待转换的高位部分；反复做除法和取余，余数按“低位 → 高位”的次序产生，而输出需要“高位 → 低位”；
- 用栈把每次得到的余数依次入栈，转换结束后再逐个出栈输出，正好把次序颠倒过来。

**例**：(1348)₁₀ = (2504)₈，其运算过程如下：

| 计算次序 | N | N div 8 | N mod 8 |
| --- | --- | --- | --- |
| 1 | 1348 | 168 | 4 |
| 2 | 168 | 21 | 0 |
| 3 | 21 | 2 | 5 |
| 4 | 2 | 0 | 2 |

计算顺序自上而下，输出顺序自下而上：依次输出 2、5、0、4，即 (2504)₈。

**算法代码**：

```c
void conversion () {
    InitStack(S);
    scanf ("%d",N);
    while (N) {
        Push(S, N % 8);
        N = N/8;
    }
    while (!StackEmpty(S)) {
        Pop(S,e);
        printf ( "%d", e );
    }
} // conversion
```

### 例二、括号匹配的检验

> 课件页码：P16–P19

**问题**：假设表达式中只含圆括号和方括号，检验其中的括号是否正确匹配。

正确的格式，例如：`([]())`、`[([][])]`。

不正确的格式，例如：`[(])`、`([())`、`(()])`。

**检验思路**：检验括号是否匹配的方法，可用“**期待的急迫程度**”这个概念来描述——每读到一个左括弧，就“期待”一个相应的右括弧；后读到的左括弧更急迫地等待匹配，最后出现的左括弧最先被匹配，与栈“后进先出”的次序一致。可能出现的不匹配情况有：

1. 到来的右括弧并非是所“期待”的；
2. 到来的是“不速之客”（此时并没有等待匹配的左括弧，却来了右括弧）；
3. 直到结束，也没有到来所“期待”的括弧（左括弧有剩余）。

**例**：考虑下列括号序列 `[ ( [ ] [ ] ) ]`，各括弧位置编号为 1～8：

| 位置 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 括弧 | `[` | `(` | `[` | `]` | `[` | `]` | `)` | `]` |

其中位置 3 与 4、5 与 6、2 与 7、1 与 8 依次配对；最后出现的左括弧（位置 5）最先被匹配，这正符合栈的后进先出规律。

**算法的设计思想**：

1. 凡出现左括弧，则进栈；
2. 凡出现右括弧，首先检查栈是否空：若栈空，则表明该“右括弧”多余；否则和栈顶元素比较——若相匹配，则“左括弧出栈”，否则表明不匹配；
3. 表达式检验结束时，若栈空，则表明表达式中匹配正确，否则表明“左括弧”有余。

**算法代码**：

```c
Status matching(string& exp) {
    int state = 1;
    while (i<=Length(exp) && state) {
        switch (exp[i]) {
            case 左括弧: { Push(S,exp[i]); i++; break; }
            case ')' : {
                if (NOT StackEmpty(S) && GetTop(S) == "(" )
                    { Pop(S,e); i++; }
                else { state = 0; }
                break;
            }
            ……
        }
    }
    if (StackEmpty(S) && state) return OK;
    ……
}
```

说明：课件代码只展开了 `(` 和 `)` 两支，`[`、`]` 的处理与之一致（扫描下标 `i` 的初值、栈 `S` 的初始化在课件中省略）；`state` 用于标记“已出现不匹配”，一旦置 0 即可提前结束循环；函数最后的 `if` 同时检查“栈空”与“state 为 1”，两者都满足才返回 OK。

### 例三、行编辑程序问题

> 课件页码：P20–P23

**问题**：如何接受用户从终端输入的一行字符？如果“每接受一个字符即存入存储器”，并不恰当——一旦发现输入有错，已存入的内容无法再更正。

**合理的作法**：设立一个**输入缓冲区**，用以接受用户输入的一行字符，然后逐行存入用户数据区；并假设 `#` 为**退格符**、`@` 为**退行符**。这样在用户输入一行的过程中，允许用户输入出差错，并在发现有误时可以及时更正。

**例**：假设从终端接受了这样两行字符：

| 终端接受的字符 | 实际有效的内容 |
| --- | --- |
| `whli##ilr#e (s#*s)` | `while (*s)` |
| `outcha@putchar(*s=#++);` | `putchar(*s++);` |

**算法代码**：

```c
while (ch != EOF && ch != '\n') {
    switch (ch) {
        case '#' : Pop(S, c); break;
        case '@' : ClearStack(S); break;    // 重置S为空栈
        default  : Push(S, ch); break;
    }
    ch = getchar();     // 从终端接收下一个字符
}
ClearStack(S);          // 重置S为空栈
if (ch != EOF)  ch = getchar();
while (ch != EOF) {     // EOF为全文结束符
    // 将从栈底到栈顶的字符传送至调用过程的数据区；
    ……
}
```

一行输入结束后，栈中自栈底到栈顶的字符即为该行的有效内容；把它依次传送至数据区，就完成了一行的“编辑—存储”。

### 例四、迷宫求解

> 课件页码：P24–P27

**问题**：给定一个迷宫（`#` 表示墙壁，空白表示通道），求一条从入口到出口的路径。课件 P24 的 10×10 迷宫示意图如下，图中箭头为探索过程中尝试过的方向，⊙ 为出口；通常用的是“**穷举求解**”的方法。

![迷宫求解：10×10 迷宫示意图，箭头为探索方向，⊙ 为出口](assets/第03章栈和队列/p024.jpg)

*图 3-3 迷宫求解：10×10 迷宫示意图（`#` 为墙壁、空白为通道），箭头为探索过程中尝试的方向，⊙ 为出口（课件 P24）*

**求迷宫路径算法的基本思想**：

- 若当前位置“可通”，则纳入路径，继续前进；
- 若当前位置“不可通”，则后退，换方向继续探索；
- 若四周“均无通路”，则将当前位置从路径中删除出去。

**算法框架**（课件 P26）：

```
设定当前位置的初值为入口位置；
do {
    若当前位置可通，
    则 {
        将当前位置插入栈顶；
        若该位置是出口位置，则算法结束；
        否则切换当前位置的东邻方块为新的当前位置；
    }
    否则 {
        ……
    }
} while (栈不空);
```

“否则”分支的处理（课件 P27）：

- 若栈不空且栈顶位置尚有其他方向未被探索，则设定新的当前位置为：**沿顺时针方向旋转**找到的栈顶位置的下一相邻块；
- 若栈不空但栈顶位置的四周均不可通，则
  - 删去栈顶位置；　　// 从路径中删去该通道块
  - 若栈不空，则重新测试新的栈顶位置，直至找到一个可通的相邻块或出栈至栈空；
- 若栈空，则表明迷宫没有通路。

**说明**：探索方向从“东邻”开始，按顺时针方向依次为东 → 南 → 西 → 北；栈中保存的是当前已纳入的路径（通道块序列），某个方向走不通就出栈、回退到上一个通道块，这就是“回溯”；算法终止有两种情形：找到出口则结束，栈空则表明迷宫没有通路。

### 例五、表达式求值

> 课件页码：P28–P36

课件先讨论表达式的三种标识方法，再讨论如何从后缀式求值，以及如何由原表达式（中缀式）求得后缀式，其中用到运算符栈与运算符优先数的比较（算符优先的思想）。

#### （一）表达式的三种标识方法

> 课件页码：P28–P30

限于二元运算符的表达式定义：

```c
表达式 ::= (操作数) + (运算符) + (操作数)
操作数 ::= 简单变量 | 表达式
简单变量 ::= 标识符 | 无符号整数
```

设 `Exp = S1 + OP + S2`（其中的“+”表示连接），则称：

| 标识方法 | 形式 | 含义 |
| --- | --- | --- |
| 前缀表示法 | `OP + S1 + S2` | 运算符在两个操作数之前 |
| 中缀表示法 | `S1 + OP + S2` | 运算符在两个操作数之间 |
| 后缀表示法 | `S1 + S2 + OP` | 运算符在两个操作数之后 |

**例如**：`Exp = a × b + (c − d / e) × f`

| 标识方法 | 表达式 |
| --- | --- |
| 前缀式 | `+ × a b × − c / d e f` |
| 中缀式 | `a × b + c − d / e × f` |
| 后缀式 | `a b × c d e / − f × +` |

**结论**：

1. 操作数之间的相对次序不变；
2. 运算符的相对次序不同；
3. 中缀式丢失了括弧信息，致使运算的次序不确定；
4. 前缀式的运算规则为：连续出现的两个操作数和在它们之前且紧靠它们的运算符构成一个最小表达式；
5. 后缀式的运算规则为：运算符在式中出现的顺序恰为表达式的运算顺序；每个运算符和在它之前出现且紧靠它的两个操作数构成一个最小表达式。

#### （二）从后缀式求值

> 课件页码：P31

如何从后缀式求值？**先找运算符，再找操作数**。

**例**：对后缀式 `a b × c d e / − f × +` 求值，按运算符出现的顺序依次结合：

| 步骤 | 运算符 | 参与运算的操作数 | 中间结果 |
| --- | --- | --- | --- |
| 1 | `×` | a、b | a×b |
| 2 | `/` | d、e | d/e |
| 3 | `−` | c、d/e | c−d/e |
| 4 | `×` | c−d/e、f | (c−d/e)×f |
| 5 | `+` | a×b、(c−d/e)×f | a×b+(c−d/e)×f |

#### （三）从原表达式求得后缀式

> 课件页码：P32–P36

**问题**：如何从原表达式求得后缀式？

**分析**：每个运算符的运算次序要由它之后的一个运算符来定；在后缀式中，优先数高的运算符领先于优先数低的运算符。对比“原表达式”和“后缀式”中的运算符：

| 表达式 | 内容 |
| --- | --- |
| 原表达式 | `a + b × c − d / e × f` |
| 后缀式 | `a b c × + d e / f × −` |

**从原表达式求得后缀式的规律**：

1. 设立运算符栈；
2. 设表达式的结束符为“#”，预设运算符栈的栈底为“#”；
3. 若当前字符是操作数，则直接发送给后缀式；
4. 若当前运算符的优先数高于栈顶运算符，则进栈；
5. 否则，退出栈顶运算符发送给后缀式；
6. “(” 对它之前后的运算符起隔离作用，“)” 可视为自相应左括弧开始的表达式的结束符。

**算法代码**（课件 P35–P36）：

```c
void transform(char suffix[ ], char exp[ ] ) {
    InitStack(S);  Push(S, '#');
    p = exp;  ch = *p;
    while (!StackEmpty(S)) {
        if (!IN(ch, OP))  Pass(Suffix, ch);
        else {
            switch (ch) {
                case '(' :  Push(S, ch); break;
                case ')' :  Pop(S, c);
                            while (c != '(') { Pass(Suffix, c);  Pop(S, c); }
                            break;
                default  :
                    while (GetTop(S, c) && (precede(c, ch)))
                        { Pass(Suffix, c);  Pop(S, c); }
                    if (ch != '#')  Push(S, ch);
                    break;
            } // switch
        }
        if (ch != '#') { p++;  ch = *p; }
        else { Pop(S, ch);  Pass(Suffix, ch); }
    } // while
} // CrtExptree
```

**代码说明**：

- `IN(ch, OP)` 判断当前字符 ch 是否为运算符，`Pass(Suffix, ch)` 把字符发送给后缀式，`precede(c, ch)` 比较栈顶运算符 c 与当前运算符 ch 的优先数；若当前字符是操作数，则直接发送给后缀式；遇 `(` 直接进栈，起隔离作用，遇 `)` 则连续出栈并发送，直到弹出 `(` 为止（`)` 本身不进入后缀式）；
- 遇其他运算符，先把栈中所有优先数不低于当前运算符 `ch` 的运算符弹出并发送，再把 `ch` 入栈（结束符 `#` 不重新入栈）；原表达式扫描完毕后，栈中剩余的运算符依次弹出并发送给后缀式，栈空时算法结束。

### 例六、实现递归

> 课件页码：P37–P42

**问题**：递归函数的执行过程中，系统如何保存各层调用的信息？

当在一个函数的运行期间调用另一个函数时，在运行该被调用函数之前，需先完成三项任务：

1. 将所有的实在参数、返回地址等信息传递给被调用函数保存；
2. 为被调用函数的局部变量分配存储区；
3. 将控制转移到被调用函数的入口。

从被调用函数返回调用函数之前，应该完成下列三项任务：

1. 保存被调函数的计算结果；
2. 释放被调函数的数据区；
3. 依照被调函数保存的返回地址将控制转移到调用函数。

**多个函数嵌套调用的规则**是“**后调用先返回**”，此时的内存管理实行“**栈式管理**”。例如 `main` 调用 `a`、`a` 调用 `b`：

```c
void main( ){        void a( ){        void b( ){
    …                    …                 …
    a( );                b( );
    …                    …
}//main              }// a             }// b
```

各函数的数据区按调用顺序依次压入，`main` 的数据区在最下面，`b` 的数据区在最上面；返回时后进先出。

**递归中的术语**：

- **递归工作栈 / 递归工作记录**：递归过程执行过程中占用的数据区称为递归工作栈；每一层的递归参数合成一个递归工作记录；
- **当前活动记录 / 当前环境指针**：栈顶记录指示当前层的执行情况，递归工作栈的栈顶指针即当前环境指针。

**例：Hanoi 塔**

```c
void hanoi (int n, char x, char y, char z) {
// 将塔座x上按直径由小到大且至上而下编号为1至n
// 的n个圆盘按规则搬到塔座z上，y可用作辅助塔座。
1   if (n==1)
2       move(x, 1, z);          // 将编号为１的圆盘从x移到z
3   else {
4       hanoi(n-1, x, z, y);    // 将x上编号为１至n-1的圆盘移到y, z作辅助塔
5       move(x, n, z);          // 将编号为n的圆盘从x移到z
6       hanoi(n-1, y, x, z);    // 将y上编号为１至n-1的圆盘移到z, x作辅助塔
7   }
8 }
```

执行 `hanoi(3, a, b, c)` 时，递归工作记录的格式为“返址 n x y z”，课件 P42 给出的记录如下：

| 记录次序 | 返址 | n | x | y | z |
| --- | --- | --- | --- | --- | --- |
| 第 1 条 | 8 | 3 | a | b | c |
| 第 2 条 | 5 | 2 | a | c | b |
| 第 3 条 | 5 | 1 | a | b | c |
| 第 4 条 | 7 | 1 | c | a | b |

说明：第 1 条是 `main` 调用 `hanoi(3, a, b, c)` 的记录；进入 `hanoi(2, a, c, b)` 后压入第 2 条；再由其第 4 行调用 `hanoi(1, a, b, c)` 压入第 3 条；它返回后执行第 5 行，由第 6 行调用 `hanoi(1, c, a, b)` 时第 4 条成为新的当前活动记录（栈顶）。递归的执行完全遵循“后调用先返回”的栈式管理。

## 3.3 栈类型的实现

> 课件页码：P43–P48

栈有两种实现方法：**顺序栈**（顺序映象）和**链栈**（链式映象）。

### 一、顺序栈的存储表示

> 课件页码：P44

```c
//----- 栈的顺序存储表示 -----
#define  STACK_INIT_SIZE  100;
#define  STACKINCREMENT   10;
typedef struct {
    SElemType  *base;
    SElemType  *top;
    int  stacksize;
} SqStack;
```

顺序栈类似于线性表的顺序映象实现，指向表尾的指针可以作为栈顶指针。各成员的含义：

| 成员 | 含义 |
| --- | --- |
| `base` | 栈底指针，指向栈底元素 |
| `top` | 栈顶指针；约定它指向栈顶元素的下一个位置（即下一个可写入的空位） |
| `stacksize` | 当前已分配的存储容量 |

- 初始时 `S.top = S.base` 表示空栈，`S.top - S.base >= S.stacksize` 时栈满、需要追加存储空间；进栈先存入、后上移（`*S.top++ = e`），出栈先下移、后取出（`e = *--S.top`）。

### 二、顺序栈的基本操作

> 课件页码：P45–P47

**构造一个空栈**：

```c
Status InitStack (SqStack &S) {// 构造一个空栈S
    S.base=(ElemType*)malloc(STACK_INIT_SIZE*sizeof(ElemType));
    if (!S.base) exit (OVERFLOW); //存储分配失败
    S.top = S.base;
    S.stacksize = STACK_INIT_SIZE;
    return OK;
}
```

**进栈**：

```c
Status Push (SqStack &S, SElemType e) {
    if (S.top - S.base >= S.stacksize) {//栈满，追加存储空间
        S.base = (ElemType *) realloc ( S.base,
                    (S.stacksize + STACKINCREMENT) * sizeof (ElemType));
        if (!S.base) exit (OVERFLOW); //存储分配失败
        S.top = S.base + S.stacksize;
        S.stacksize += STACKINCREMENT;
    }
    *S.top++ = e;
    return OK;
}
```

**出栈**：

```c
Status Pop (SqStack &S, SElemType &e) {
    // 若栈不空，则删除S的栈顶元素，
    // 用e返回其值，并返回OK；
    // 否则返回ERROR
    if (S.top == S.base) return ERROR;
    e = *--S.top;
    return OK;
}
```

### 三、链栈

> 课件页码：P48

课件用示意图给出链栈的存储结构：

![链栈：栈顶指针指向 an，结点指针由 an 指向 a1](assets/第03章栈和队列/p048.jpg)

*图 3-4 链栈：栈顶指针指向 a_n，结点指针由 a_n 指向 a_1（课件 P48）*

- 栈顶指针指向栈顶结点 a_n，各结点通过指针依次链接 `a_{n-1}`、…、`a_1`，最后一个结点的指针域为 ∧；
- 课件特别提示“**注意：链栈中指针的方向**”——链栈的指针方向与一般线性链表的方向相反，是从栈顶指向栈底，即栈顶在表头、栈底在表尾；因此链栈的入栈、出栈都发生在表头（栈顶指针所指位置），只需修改表头指针，不必像顺序栈那样移动元素；课件只给出示意图和上述提示，未给出链栈的操作代码。

## 3.5 队列类型的实现

> 课件页码：P58–P70

队列有两种实现方法：**链队列**（链式映象）和**循环队列**（顺序映象）。

### 一、链队列——链式映象

> 课件页码：P59–P63

**结点类型**：

```c
typedef struct QNode {// 结点类型
    QElemType      data;
    struct QNode  *next;
} QNode, *QueuePtr;
```

**链队列类型**：

```c
typedef struct { // 链队列类型
    QueuePtr  front;  // 队头指针
    QueuePtr  rear;   // 队尾指针
} LinkQueue;
```

![链队列示意：Q.front 指向头结点，Q.rear 指向队尾结点 an；空队列时两指针指向同一头结点](assets/第03章栈和队列/p060.jpg)

*图 3-8 链队列示意：非空队列中 `Q.front` 指向头结点、`Q.rear` 指向队尾结点 a_n；空队列时两指针均指向头结点，`Q.front->next` 为 ∧（课件 P60）*

- 链队列为便于操作，设置一个**头结点**：`Q.front` 指向头结点，队头元素存放在 `Q.front->next` 所指结点；`Q.rear` 指向队尾结点；空队列的判定为 `Q.front == Q.rear`（且 `Q.front->next == NULL`）；
- 入队只需在表尾插入结点并修改 `Q.rear`，出队只需删除头结点之后的第一个结点并修改 `Q.front`。

**构造一个空队列**：

```c
Status InitQueue (LinkQueue &Q) {
    // 构造一个空队列Q
    Q.front = Q.rear =
                (QueuePtr)malloc(sizeof(QNode));
    if (!Q.front) exit (OVERFLOW);
                                             //存储分配失败
    Q.front->next = NULL;
    return OK;
}
```

**入队**：

```c
Status EnQueue (LinkQueue &Q, QElemType e) {
    // 插入元素e为Q的新的队尾元素
    p = (QueuePtr) malloc (sizeof (QNode));
    if (!p)  exit (OVERFLOW);   //存储分配失败
    p->data = e;   p->next = NULL;
    Q.rear->next = p;    Q.rear = p;
    return OK;
}
```

**出队**（若删除的是队尾结点，需令 `Q.rear` 重指向头结点）：

```c
Status DeQueue (LinkQueue &Q, QElemType &e) {
    // 若队列不空，则删除Q的队头元素，
    //用 e 返回其值，并返回OK；否则返回ERROR
    if (Q.front == Q.rear)    return ERROR;
    p = Q.front->next;   e = p->data;
    Q.front->next = p->next;
    if (Q.rear == p)  Q.rear = Q.front;
    free (p);      return OK;
}
```

### 二、循环队列——顺序映象

> 课件页码：P64–P67

**顺序队列类型**：

```c
#define MAXQSIZE  100  //最大队列长度
typedef struct {
    QElemType  *base;  // 动态分配存储空间
    int  front;     // 头指针，若队列不空，指向队列头元素
    int  rear;      // 尾指针，若队列不空，指向队列尾元素的下一个位置
} SqQueue;
```

- 用一维数组 `base[0 .. MAXQSIZE-1]` 存放元素，`front`、`rear` 是数组下标；入队时 `rear` 前移、出队时 `front` 前移，二者都按模 `MAXQSIZE` 循环，即 `rear = (rear+1) % MAXQSIZE`、`front = (front+1) % MAXQSIZE`，从而重复利用数组空间；
- **队空条件**：`Q.front == Q.rear`；**队满条件**：`(Q.rear + 1) % MAXQSIZE == Q.front`（队满时仍保留一个空单元，队列最多存放 `MAXQSIZE - 1` 个元素）；**队列长度**（元素个数）：`(Q.rear - Q.front + MAXQSIZE) % MAXQSIZE`。

**构造一个空队列**：

```c
Status InitQueue (SqQueue &Q) {
    // 构造一个空队列Q
    Q.base = (ElemType *) malloc
            (MAXQSIZE *sizeof (ElemType));
    if (!Q.base) exit (OVERFLOW);
                                           // 存储分配失败
    Q.front = Q.rear = 0;
    return OK;
}
```

**入队**：

```c
Status EnQueue (SqQueue &Q, ElemType e)
{   // 插入元素e为Q的新的队尾元素
    if ((Q.rear+1) % MAXQSIZE == Q.front)
        return ERROR; //队列满
    Q.base[Q.rear] = e;
    Q.rear = (Q.rear+1) % MAXQSIZE;
    return OK;
}
```

**出队**：

```c
Status DeQueue (SqQueue &Q, ElemType &e)
{  // 若队列不空，则删除Q的队头元素，
   // 用e返回其值，并返回OK;  否则返回ERROR
    if (Q.front == Q.rear)  return ERROR;
    e = Q.base[Q.front];
    Q.front = (Q.front+1) % MAXQSIZE;
    return OK;
}
```

### 三、循环队列的应用：二项式系数（杨辉三角）

> 课件页码：P68–P70

二项式系数值构成杨辉三角，课件列出前四行：

| 行 | 二项式系数值 |
| --- | --- |
| 第 1 行 | `1 1` |
| 第 2 行 | `1 2 1` |
| 第 3 行 | `1 3 3 1` |
| 第 4 行 | `1 4 6 4 1` |

**递推规律**：设第 i-1 行的值（两边补 0）为 `(a[0]=0) a[1]..a[i] (a[i+1]=0)`，则第 i 行的值为：

```
b[j] = a[j-1] + a[j]，j = 1, 2, …, i+1
```

**利用循环队列计算**：假设只计算四行，则队列的最大容量为 5；每行以 `0` 作为结束标记，其核心操作代码为：

```c
do {
    DeQueue(Q, s);
    GetHead(Q, e);
    if (e != 0) printf ("%d", e);
    EnQueue(Q, s + e);
} while (e != 0);
```

`s` 保存刚出队的元素，`e` 是出队后的新队头；`s + e` 正是杨辉三角中“上一行相邻两项之和”，入队后即为下一行的对应系数；当 `e = 0` 时表示本行处理完毕（`0` 是行结束标记），此时队列中已存入下一行的系数，可进入下一行计算。

## 本章要点回顾

> 课件页码：P71

1. **栈和队列的定义**：二者都是限定插入和删除只能在表的“端点”进行的线性表。栈的插入、删除都在同一端（栈顶）；队列在表尾插入、表头删除。
2. **栈与队列的 ADT**：数据对象、数据关系与线性表相同；栈约定 a_n 端为栈顶、a_1 端为栈底，队列约定 a_1 端为队列头、a_n 端为队列尾；两者各有 9 个基本操作（InitStack、DestroyStack、ClearStack、StackEmpty、StackLength、GetTop、Push、Pop、StackTravers 与 InitQueue、DestroyQueue、QueueEmpty、QueueLength、GetHead、ClearQueue、EnQueue、DeQueue、QueueTravers）。
3. **数制转换**：由 `N = (N div d)×d + N mod d` 反复取余，余数入栈后逆序输出，即得 d 进制数的各数位。
4. **括号匹配**：左括弧入栈；右括弧与栈顶比较，匹配则出栈，不匹配立即判错；结束时栈空才说明匹配正确。
5. **行编辑**：以输入缓冲区加栈实现，`#` 退格（出栈一个字符）、`@` 退行（清空栈）。
6. **迷宫求解**：用栈保存当前路径；可通则进栈前进，不可通则换方向或出栈回退；栈空表明迷宫无通路。
7. **表达式求值**：有前缀、中缀、后缀三种标识；后缀式中运算符出现的顺序恰为运算顺序；借助运算符栈与优先数比较，可由原表达式求得后缀式。
8. **递归**：函数嵌套调用遵循“后调用先返回”，内存管理实行“栈式管理”；递归工作栈保存每一层的参数与返回地址，栈顶记录即当前活动记录。
9. **栈的实现**：顺序栈用 `base`、`top`、`stacksize` 描述，栈空条件为 `top == base`，栈满条件为 `top - base >= stacksize`；链栈的指针方向由栈顶 a_n 指向栈底 a_1。
10. **队列的实现**：链队列用 `front`、`rear` 两个指针，空队列时 `front == rear`；循环队列队空条件为 `front == rear`，队满条件为 `(rear+1) % MAXQSIZE == front`，队列长度为 `(rear - front + MAXQSIZE) % MAXQSIZE`。
11. 课件 P71 归纳本章应掌握的内容：栈和队列的特点及在应用问题中的正确选用；栈的两种实现方法，特别是栈满、栈空条件；循环队列和链队列的基本操作实现，特别是队满、队空的描述方法；递归算法执行过程中栈的状态变化。
